# Terralyt

Geospatial intelligence platform for Pakistani housing societies. FAST-NUCES (Chiniot-Faisalabad) Final Year Project, 2026.
Team: Taha Saleem Sheikh (23F-0517), Muhammad Mursaleen Mustafvi (23F-0659), Rahmeen Nasr (23F-0700). Supervisor: Ms. Mahzaib Younas.

Terralyt shows a housing society as an interactive 3D map, rates its development Low / Medium / High from satellite data, and gives a 5-year forecast. Users: buyers, investors and overseas Pakistanis who cannot visit the society. Pilot society: **FDA City, Faisalabad** (OSM centre 31.525 N, 73.088 E, next to the M-3/M-4 motorways).

## Repo layout

- `*.html` + `assets/app.js` + `assets/style.css`: the UI. **Plain HTML, CSS and JavaScript, not React.** No `package.json`, no npm, no build step.
- `assets/app.js`: shared helpers and sample `PLOTS` (60 plots) used by `plot.html`, `search.html` and the top search bar. `badge()` and `qs()` are used by every page.
- `assets/iso.js`: the old drawn (SVG) demo map; still used by `plot.html`.
- `map.html`: two views of the society. **3D society model** (three.js, default tab) and **Real-world map** (CesiumJS, loaded only when its tab is opened). **Full screen**: the button under the compass or the F key puts the map stage (either view) in full screen with the search box and the selected plot's details floating over it (`toggleFullscreen` in `map.html`; falls back to filling the window where the Fullscreen API is missing). **Turning and tilting** without a right mouse button: the buttons under the compass (hold to keep turning), dragging the compass, the arrow keys, Shift + drag (`api.turn(deg, tilt)`).
- `assets/society3d.js`: the three.js scene (ground, roads, lane markings, street lights, trees, traffic, plots, houses standing today, landmarks, the main gate, labels, picking, day/evening/night, satellite ground, mini-map).
- `assets/models3d.js`: procedural 3D models for every landmark type on the official FDA City maps, the main gate (`buildGate`) and the house (`buildHouse`), plus materials: photo textures from `assets/tex/` (CC0 photographs from ambientCG, tinted to the map's colours; `usePhoto`, credits in `assets/tex/README.md`, rebuilt by `tools/make_textures.py`) with drawn canvas textures as the fallback.
- `assets/map3d.js`: the CesiumJS real-world view.
- `data/*.geojson`: map data generated by `tools/make_data.py` from `tools/source/`: `plan_features.json` (features digitised from the official FDA City plan and block maps, with georeference control points), `osm_fda_area.json` (OpenStreetMap streets), `nala_traced.geojson` (storm drain traced on satellite imagery). The plan image is downloaded to `tools/source/cache/` (git-ignored) and its colours give each street block's plot size.
- `tools/emap_plan.py`: **the current plot source.** Downloads the whole FDA City plan from emap.pk (zoom-19 tiles, newer revision with Block X), segments every plot, registers the plan to the OpenStreetMap streets with a displacement field (0.65 m median residual), reads the printed plot numbers (Tesseract, `winget install UB-Mannheim.TesseractOCR`; RapidOCR through `tools/rapid_ocr.py` in Python 3.12, `py -3.12 -m pip install rapidocr_onnxruntime`; plus a digit recogniser, combined by vote and checked against the neighbours) and writes `tools/source/emap_layout.json`, `emap_road.png`, `emap_plotcol.png`. `make_data.py` uses them when present (`--sheets` falls back to the block maps below). About 30 minutes; rerun only to re-read the plan.
- `tools/trace_plots.py`: (older source, used with `make_data.py --sheets`) reads the plot outlines and street corridors off the six official block maps (downloaded into `tools/source/cache/`), registers each sheet to the OpenStreetMap streets (about 2 to 3 m rms) and writes `tools/source/sheet_layout.json`, `sheet_ink_A..F.png` and `sheet_road_A..F.png` (the street space of each sheet). Needs `pip install opencv-python-headless scikit-image scipy`. Rerun it only when re-reading the sheets; `--debug DIR` writes an overlay image per sheet.
- `tools/align_roads.py`: measures the sideways offset of each main OpenStreetMap way on Google satellite imagery (zoom 19) and writes `tools/source/road_offsets.json`, which `make_data.py` applies. Run after `make_data.py`, then run `make_data.py` again.
- `tools/source/buildings_fda.geojson`: building footprints detected on satellite imagery (Google Open Buildings 2023, Microsoft ML Buildings, from Overture Maps). They decide which plots are built and where houses stand.
- `tools/trace_sheets.py`: the digitisation of Blocks B to F from their own block maps (feature boxes, control points); it rewrites the B to F entries of `plan_features.json`. Needs the sheet images and detected picture boxes in a working folder, so rerun it only when re-tracing.
- `tools/audit.py`: checks the generated data against the layout rules (no overlaps, every plot fronts a road, no bare land, facility areas against the official kanal figures). Run it after every regeneration.
- `tools/service_roads.py`: finds the service roads beside the main road (boulevard and main entrance road) that OpenStreetMap lacks. Google Maps (road map without labels, zoom 19) decides where a service road exists; its centre line is measured on Google satellite imagery (zoom 19). Writes `tools/source/service_roads.geojson`; `make_data.py` adds these as class `service` (`source: Measured ...`) and cuts back OpenStreetMap streets drawn along them. Run after `make_data.py`, then run `make_data.py` again.
- `tools/overlay.py`: draws the generated data over Google satellite (`--base sat`), the Google road map (`map`, `mapnl` without labels, `mix`) or the emap.pk plan (`plan`) for any spot, for checking: `python -I tools/overlay.py LAT LON --size 200 --base sat --layers roads,surface,plots,land,water --out out.png`.
- `tools/shoot.py`: headless-browser screenshot of the map for visual checks (Playwright, uses installed Chrome). Run one capture at a time: software rendering is slow and parallel runs time out.

## Run locally

1. Optional: copy `assets/config.example.js` to `assets/config.js` and paste a Cesium ion token (only the Real-world tab uses it). `config.js` is git-ignored; never commit it. Without a token Cesium uses OpenStreetMap tiles and flat ground.
2. `python -m http.server 8000` in the repo root (opening files directly breaks `fetch` of the GeoJSON and ES modules).
3. Open `http://localhost:8000/map.html`. URL options: `?id=2500` or `?plot=B-12` selects a plot, `?lm=12` a landmark (`?lm=121` is the main gate), `?time=evening` or `?time=night`, `?ground=satellite`, `?view=earth`.

Regenerate data: `python -I tools/make_data.py --preview preview.png` (needs `pip install shapely numpy pillow matplotlib`). Then run `python -I tools/audit.py`. To move a park, mosque or zone, edit its pixel box in `tools/source/plan_features.json` and regenerate. Each entry is in pixels of a map sheet: `"sheet": "A"` to `"F"` are the block maps from fdacity.pk (each block's pages stacked top to bottom; page URLs are listed under `sheets`), and the default sheet is the 1600x1152 overall plan, now used only for the south-west tip of Block F, the grid station, graveyard and sewerage works. Each sheet has its own control points: roundabout centres (exact) plus parks that also appear on the overall plan; sheets C and D are tied to the boulevard axis because their second roundabout is not built yet. `kanal` is the area printed on the official map; the generator sizes the site to match it.
Screenshot test: `python -I tools/shoot.py http://127.0.0.1:8000/map.html out.png --js "window.__map.select(2500)"` (needs `pip install playwright`).

## 3D society model (`assets/society3d.js`, three.js r169)

- Loaded as an ES module through the import map in `map.html` (three.js and `three-mesh-bvh` from jsDelivr). No build step.
- Lighting: soft sun shadows (`PCFShadowMap`, `shadow.radius`, `shadow.intensity` .86), walls darker towards the ground (`groundShade`), soft contact shadows round buildings (`aoSkirt`, material `M.ao`: not pickable, casts no shadow; its vertex alpha must survive the merges) and under trees. Weak devices (`lowEnd`) skip the anti-repeat ground shader and the tree shadows (`createMaterials({ lite })`).
- Light from the sky (`setSkyLight`: the environment map is rendered from the sky without its sun disc, again at each time-of-day change) and distance haze (`FogExp2`). Ambient occlusion (N8AO from jsDelivr, loaded only when on; `setAO`) with SMAA; `opts.quality` / `?quality=auto|high|fast` and the Graphics button in `map.html` (`setQuality`, `aoActive()`); Auto switches it on when a frame takes under 20 ms without it. The import map also needs `three/examples/jsm/` and `postprocessing` for N8AO.
- Level of detail (`lodItems`, `updateLod`): trees are instanced per 600 m patch as leaf cards near the camera (`treeNear`, `M.foliage`, `assets/tex/foliage.webp` from `tools/make_foliage.py`) and low-poly crowns far away (`treeFar`); house parts tagged `k.level = 1` in `buildHouse` are merged per 500 m patch and drawn only near the camera. Keep new small house parts after `k.level = 1`.
- `Society3D(element, { onPick, onHover, onStatus, layer })` returns `{ ready, setLayer, setTime('day'|'evening'|'night'), setGround('plan'|'satellite'), setLabels, select(plotId), selectLandmark(id), clearSelection, reset, zoomIn, zoomOut, flyToBlock, search, get, getLandmark, plots, landmarks, rendered }`. `map.html` exposes it as `window.__map`.
- Layers: `cls` (development class), `stat` (plot status), `sat` (built / vacant). Colours match the legend in `map.html`.
- Coordinates: local metres around the society centre (`x` east, `z` = -north), same equirectangular constants as `tools/make_data.py` (`LAT_REF` 31.525).
- Performance rules: plots are one merged mesh with per-vertex colours and a `pid` attribute for picking; every landmark is built in a local group then merged by material (attribute `lmid` for picking); trees, lamps and cars are `InstancedMesh`. Keep it that way: thousands of separate meshes would be too slow.
- Every model is laid out inside the largest rectangle that fits in the real site polygon, avoiding the plots the plan puts inside a site (polygon holes, passed to `makeKit(..., holes)`) (`inscribedRect` in `society3d.js`), and scaled down when the site is smaller than the model (`MIN_SITE`); ground and boundary wall follow the true outline. Open `map.html?audit=1` and read `window.__map.modelAudit` to list any model part more than 1.5 m outside its site: it must stay empty.
- Land the official map only labels as reserved (Area for FDA City Homes, Multi-Purpose Uses) is drawn as open ground with a wall and signboard (`reserved()` in `models3d.js`), not as invented buildings.
- Houses: `buildHouses()` in `society3d.js` reads `data/buildings.geojson`, builds one illustrative house per footprint with `buildHouse` (real position and footprint size, assumed look and storeys; plinth, sunshades, feature panel, car porch with terrace, parapet, stair room, tanks, solar panels on half the roofs), turns each house so its front (+X) faces the nearest street, adds a boundary wall and gate to every built plot (gate on the street side), and merges everything by material with a `pid` attribute, so clicking a house selects its plot. Houses appear only where a building stands today; all other plots stay land. A footprint covering a good part of a neighbouring plot (30 m2 and a fifth of it) is split at the plot line and both plots are built; one that only pokes over is trimmed to its own plot; each house is drawn in the largest rectangle inside its piece (`inscribed_rect` in `make_data.py`), so no house crosses a plot line (checked by `audit.py`).
- The main gate is a Point feature (`kind: gate`, `heading`, `span`, `asphalt`: the paved bands across it in the model's frame) in `landmarks.geojson`; `buildOne` places `buildGate` across the Main Entrance Road with its towers beyond the outermost asphalt and pier, guard room and barriers on the median. No tree or lamp is placed on asphalt (`asphaltIndex` in `society3d.js`).
- Landmark builders live in `models3d.js` (`B.mosque`, `B.school`, ... `buildGate`). They work in a local frame (X = long axis, length L; Z = width W) and add parts through the kit (`k.box`, `k.building`, `k.tree`, `k.sign`, `k.fillTrees`, ...). Signs and flags keep their own materials (`keep: true`).
- The drawn 3D ground is the default. The "Satellite photo" button (or `?ground=satellite`) streams Esri World Imagery tiles with a quadtree level of detail (zoom 13 to 19) under the plan; attribution is shown on screen.
- Road sizes: right of way from the official maps (202, 110, 85, 60, 40 ft); paved carriageway widths measured on z19 satellite imagery (see `WIDTH`, `ROW` and the comment in `tools/make_data.py`). The boulevard and the main entrance road have service roads on both sides wherever Google Maps shows one (OpenStreetMap plus `tools/service_roads.py`), paved strips with painted kerbs between, and two carriageways of two lanes each (dashed lane line in the middle, solid edge lines, as seen on Google satellite imagery) with a planted median; service roads carry no painted lines (none on site); traffic keeps to the left on two-way roads; the 110 ft road in Block A is a dual road with a median; roundabout islands are 60 m across (south-west one 46 m). Verges are drawn separately from asphalt; medians and islands have painted kerbs.
- Layout rules enforced by the generator and checked by `tools/audit.py`: no plot overlaps a road, the nalla, a facility or another plot; plots front a road (streets between plot groups are the centre lines of the corridors between placed plots, kept where the block map shows street space: `corridor_lines` in `make_data.py`, 5 m carriageway in a 40 ft reserve; planned 40 ft streets are inserted in deep generated street blocks, `planned: true` in `roads.geojson`; the audit reports the official plots with no street within 6 m); land that is not road, plot or facility becomes green open space (`layer: green` in `blocks.geojson`); society land that every block map shows blank gets no plots (`layer: open`, drawn as bare scrub).
- Layers: `real` (default: plots as vacant land, as on site today), `cls`, `stat`, `sat`, `size` (5/10/20 Marla, Commercial). `setFilter({sizes, statuses, block})` greys out plots that do not match. Clicking a block label or block button shows block statistics. The Tour button flies through the main places.
- `onPick(props)` receives plot properties, landmark properties with `landmark: true`, or `null`; `map.html` renders the side panel from them.

## Real-world map (`assets/map3d.js`, CesiumJS 1.119)

- Draws the plots (flat land parcels), the houses standing today (footprints extruded to their assumed height; clicking one selects its plot), parks, roads, block labels and the main gate.

- `Map3D(elementId, { onPick, onHover, onStatus, layer })` with `setLayer`, `select`, `reset`, `zoomIn`, `zoomOut`, `flyToBlock`, `search`. World Terrain + World Imagery when a token is set.
- Plots are one batched `Primitive`. Rings must not repeat the closing point or contain duplicate points (`toCart(ring, true)`), otherwise Cesium's worker throws "normalized result is not a number" and rendering stops.

## Data format (`data/`, GeoJSON, EPSG:4326 / WGS84)

| File | Geometry | Source |
| --- | --- | --- |
| `boundary.geojson` | Polygon, props `centre_lon/lat`, `axis_deg` | OpenStreetMap way 287541676 (georeferenced) |
| `roads.geojson` | LineString, props `class` (main, service, divider, divider_half, road110, road85, collector, residential, roundabout, arterial, highway), `width_m`, `official_ft`, `oneway`, `planned` | OpenStreetMap centrelines (georeferenced); planned streets from the generator |
| `road_surface.geojson`, `outer_roads.geojson` | Polygon, `kind` carriageway or verge | centrelines buffered to measured widths (approximate) |
| `blocks.geojson` | Polygon, props `layer` (land, inner, green), `kind` (parcel, greenbelt, median, strip, island, green), `use` | faces of the road network (approximate) |
| `water.geojson` | Polygon, LineString, Point; `kind` nala_water, nala_wall, nala_bank, nala_line, nala_tree, bridge | Barani Nala traced from Esri World Imagery (approximate) |
| `landmarks.geojson` | Polygon (Point for the gate, with `heading` and `span`), props `kind`, `name`, `block`, `area_kanal`, `proposed`, `obb` | placed per the official FDA City block maps (approximate); gate position measured on satellite imagery |
| `buildings.geojson` | Polygon, props `plot_id`, `plot_no` (absent when the house is on no plot), `storeys`, `height`, `obb`, `dataset` | building footprints detected on satellite imagery; storeys assumed |
| `parks.geojson` | Polygon | landmark footprints for the CesiumJS view |
| `plots.geojson` | Polygon | official outlines read from the block maps where the print is clear, otherwise generated inside the street block at the official size (`layout` says which) |

Landmark kinds: highschool, postoffice (post office, police station and telephone exchange), community, hotel, firestation, office, shops, mosque, school, playground, commercial, dispensary, park, hospital, sports, civic, university, stadium, cinema, multipurpose, homes, grid, graveyard, cng, shrine, metro, sewerage, roundabout (monument: rings, tree, fountain). Landmarks with `outside: true` are shown on the official plan but lie outside the society.

Plot properties: `id`, `plot_no` (block and the number printed on the plan, e.g. `D-108`; `D-108 (D2)` with the estimated sub-block where a number repeats in a block; `X-u12` when no number could be read), `plot_number`, `sub_block` (estimated), `number_source`, `marla`, `block`, `size` (5/10/20 Marla or Commercial), `type`, `status` (Available, Reserved, Sold, Unknown; a sample value), `dev_class` (High, Medium, Low: share of built plots within 150 m, `built_share_150m`), `built` (a building footprint stands on the plot), `built_source`, `storeys`, `height` (m), `height_source` (`assumed`), `source`, `confidence`, `lat`, `lon`, `area_m2`, `layout` (`FDA City plan (emap.pk), registered to the streets`, `Gap in a row of the plan (outline not readable)`, or `Generated in the street block`; with `--sheets`: `Official block map`), `accuracy`.

**The layout follows the FDA City plan published on emap.pk, registered to the real streets (0.65 m median). 13,059 plots in Blocks A to F and X; 13,057 are outlines from the plan; plot numbers are the ones printed on it (OCR: 97.3% numbered, about 98.5% of those right); sub-blocks are estimated. Built / vacant and the development class come from building footprints; status and storeys are samples.** Real plot records and model output will replace them with the same file and property names; the map code should not need changes. Block letters A–F follow the official layout (A, B, C north-west of the 202 ft boulevard, F, E, D south-east); the split points between blocks are approximate. Block A follows its own block map: Markazi Park (74.76 kanal), Girls and Boys High Schools, post office / police station / telephone exchange, Jamia Masjid, community centre, five star hotel site, commercial zone, hospital, fire brigade, PMU office and parks A-1 to A-7.

## Rules that come from the project documents

- When the proposal and the use case diagram disagree, **the use case diagram wins**.
- Actors: End User, Society Head, System Administrator. Secondary: AI/ML Model, Cesium Js.
- Forecast horizon is **5 years**, always labelled as a model estimate with uncertainty.
- Plot status comes from verified records only, never from satellite imagery alone, and is shown with its source and confidence.
- There is **no plot-comparison feature** (no use case for it).
- Heights are assumed (3.5 m per storey) until real data exists; label them as assumed.

## Known gaps

- Plots come from emap.pk (a third-party redraw of the FDA plan); 2.7% have no readable number, about 1.5% of numbers are OCR errors, sub-blocks are estimated, and the building footprints date from about 2023. See `HANDOVER.md` sections 9 to 11 for the audit figures and the next steps.
- `plot.html` and the top search bar still use the 60-plot `PLOTS` sample from `app.js`, so they do not know the map plots. The map side panel shows full details itself and links only to `trends.html`. Mursaleen to decide how `plot.html` should load from `data/plots.geojson`.
- `assets/bg.js` throws a `drawImage` TypeError at line 698 on every page when its background image is not yet loaded (pre-existing on `main`, harmless but noisy).
- Report and README say React.js and scikit-learn; the actual UI is plain HTML/JS and the model plan is PyTorch. Some diagrams still mention plot comparison.
- The report's tools section should add three.js (detailed 3D society model) next to CesiumJS (real-world view).
